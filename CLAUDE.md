# Daypack

Mobile-first nursery packing list for parents (one-handed use). See [SPEC.md](SPEC.md) for scope and [DESIGN.md](DESIGN.md) for all styling.

## Stack
Preact + Vite + TypeScript (`/frontend`), Panda CSS, Hono on Cloudflare Workers (`/backend`), npm workspaces. One Worker serves the built frontend (static assets, SPA fallback) and the API under `/api`. State lives in localStorage as the offline cache and syncs through the Worker to a shared household store in D1 (MVP slice 4, see SPEC.md).

## Layout
- `frontend/` Vite app: `src/components`, `src/i18n` (`en.ts`, `sv.ts`), `src/state`, `src/icons`
- `backend/` Hono app: `src/index.ts`, `src/routes` (household, sync), `src/auth.ts`; D1 schema in `migrations/`
- `wrangler.jsonc` (root): Worker + assets config
- `DESIGN.md`, `SPEC.md`

## Commands
Filled in as each step lands; "TBD" means not set up yet.
- Dev API: `npm run dev -w backend` (wrangler dev on :8787; needs `frontend/dist` to exist). Frontend dev: `npm run dev -w frontend` (Vite on :5173, `/api` proxied to :8787)
- Local database: `npx wrangler d1 migrations apply daypack --local --config ../wrangler.jsonc` (run in `backend/`; once, and after adding a migration). Before the first deploy: `wrangler d1 create daypack`, put its id in `wrangler.jsonc`, then `migrations apply daypack --remote` (ask the user first)
- Regenerate Worker types after editing wrangler.jsonc: `npm run types -w backend`
- Build: `npm run build` (outputs `frontend/dist`; `styled-system/` is generated by `npm install` via `prepare`)
- Preview production build on one port: `npm run preview` (build, then wrangler dev on :8787 serving app + API)
- Check everything: `npm run check` (lint, typecheck, tests)
- Typecheck: `npm run typecheck` (runs each workspace's `typecheck` script)
- Lint: `npm run lint`
- Test: `npm test` (runs each workspace's `test` script; Vitest in backend and frontend)
- Deploy: `npm run deploy` (check, build, `wrangler deploy`; publishes publicly and needs a Cloudflare login, so ask the user before running). Safe validation: `npm run deploy:dry-run -w backend`

## Rules
- Language: ALL code is English (identifiers, file names, comments, commit messages, test names, API fields). The only non-English text is user-facing strings inside the translation files.
- Every user-facing string goes through the translation dictionary; `sv` must have exactly the same keys as `en`.
- All styling follows DESIGN.md and uses Panda tokens only; no hard-coded colors or sizes in components.
- Every tap target is at least 48×48px.
- The backend targets Cloudflare Workers: no Node-only APIs. Backend tests run against a real local D1 (`getPlatformProxy`), not a mock.
- Sync: the client only queues the keys of unsent changes and reads values at push time; new local mutations must mark `pending`, remote ones must not.

## Conventions
- Strict TypeScript; no `any`. Small, single-purpose components.
- No new dependencies without asking.
- Comments explain why, not what. Match the surrounding code's style.
- Item ids are stable English slugs; never key persisted state on labels.
- Wrap localStorage access in try/catch and validate what is read.
- Motion must respect prefers-reduced-motion (swap durations to the `none` token; strict tokens reject `'none'`).
- Panda gotchas: gradient tokens need the reference form (`backgroundImage: '{gradients.accent}'`, the bare name emits an empty rule); token names must be static, so per-hue styles are spelled out in `cva` (`components/hueStyles.ts`); don't name a size token `screen` (Panda maps it to `100vh`).
